01 / Project Overview

项目目标与问题背景

课题背景

传统图像识别系统通常只能输出类别、标签或固定格式的检测结果，难以支持用户围绕同一张图片进行自然语言追问。随着大语言模型的发展，视觉信息需要被转化为语言模型可理解的上下文，才能形成“看图、理解、回答、追问”的完整交互链路。

本课题围绕轻量级多模态大模型展开，目标是在有限训练资源下，将 CLIP 的视觉表征能力与 Qwen3-1.7B 的语言生成能力连接起来，并进一步通过指令微调和 LoRA 适配，使系统具备图像描述、视觉问答、多轮对话和风格化回复能力。

研究目标

完成一个从模型训练到 Web 部署的 Mini-LLaVA 智能视觉对话系统，证明轻量架构也能够实现可演示、可交互、可扩展的多模态应用闭环。

问题 1：视觉特征接入语言模型 CLIP 输出的是视觉 token，Qwen3 接收的是语言嵌入。系统通过 MLP Projection 将 768 维视觉特征映射到语言模型隐藏空间，解决跨模态对齐问题。
问题 2：从图像描述到指令问答 单纯 caption 训练只能让模型描述图片。Stage 2 使用单轮和多轮图文对话数据，使模型学习根据用户问题组织回答。
问题 3：系统演示与部署落地 训练得到的权重需要被加载到可访问的交互界面中。系统使用 Gradio 封装推理流程，支持图片上传、对话历史、人格切换和移动端访问。

系统范围

本设计覆盖数据处理、模型结构、三阶段训练、推理封装、Web 交互和功能测试，不只停留在模型训练脚本层面。

  • 模型侧：实现 CLIP 视觉编码、MLP 跨模态投影、Qwen3-1.7B 语言生成的组合。
  • 训练侧：通过 Stage 1、Stage 2、Stage 3 逐步获得描述、问答、风格化交互能力。
  • 系统侧：将训练权重加载到 Gradio Web 服务，支持图片上传、自然语言提问、多轮历史和移动端扫码。
  • 展示侧：用网页将实验路线、关键代码、结果指标和部署方式完整串联。

预期能力

  • 图像描述：用户只上传图片时，系统自动生成图像内容说明。
  • 视觉问答：用户可以围绕主体、场景、动作和细节进行提问。
  • 多轮追问：同一张图像下保留历史上下文，支持连续对话。
  • 风格切换：通过 LoRA adapter 在默认助手和不同人格风格之间切换。

02 / System Architecture

系统总体架构

交互层
用户输入 图片上传 / 摄像头拍摄 / 文本提问 / 多轮追问
Gradio Web 聊天窗口、人格下拉框、二维码移动端访问
模型层
CLIP ViT-B/16 输出 197 个视觉 token，保留图像空间信息
MLP Projection Linear → GELU → Linear，将 768 维视觉特征映射到 Qwen3 嵌入空间
Qwen3-1.7B 接收视觉嵌入、用户问题和历史对话，自回归生成回答
训练层
Stage 1 冻结 CLIP + LLM，只训练 Projection，建立模态对齐
Stage 2 加载 Projection，训练 Projection + LLM，获得视觉问答和多轮能力
Stage 3 注入 LoRA adapter，低成本扩展不同回复风格
设计思路：CLIP 负责把图像转成视觉特征，Projection 负责把视觉特征转换到语言模型能理解的向量空间，Qwen3-1.7B 负责结合问题与历史上下文生成自然语言回答。

03 / Data Processing

实验数据处理流程

图像处理流水线

训练和推理使用同一套 CLIP 标准预处理，保证输入分布一致。

Resize 224 CenterCrop ToTensor Normalize [3,224,224]
  • Stage 1 从 SA1B-Dense-Caption 的 URL 下载图像，失败自动重试并跳过异常样本。
  • Stage 2 从 CogVLM-SFT-311K 本地图片与 JSON 标签读取单轮、多轮对话。
  • Stage 3 读取蒸馏后的风格 JSON，并复用 Stage 2 的多轮对话构造方式。

文本监督策略

训练不是让模型预测所有输入 token，而是只监督 assistant 需要回答的部分。

visual tokens: -100 user prompt: -100 assistant answer: loss

这样模型会学习“看图后如何回答”，而不会把用户问题或视觉 token 当作需要复述的目标。

图像预处理一致性CLIP 训练时使用固定的 224×224 输入和归一化参数。训练和推理保持同一预处理，可以减少视觉特征分布漂移，让 Projection 学到的映射关系更稳定。
监督目标设定用户问题是条件，assistant 回复才是生成目标。将 user 轮、视觉 token 和 padding 位置设为 -100 后，loss 会集中反映模型回答能力。
多轮编码方式Qwen3 的 chat template 和 BPE 分词依赖上下文边界。完整前缀编码后再取新增 token，可避免逐轮拼接造成 input_ids 与 labels 错位。

05 / Stage 1 Modality Alignment

Stage 1：模态对齐训练

训练目的

让 CLIP 输出的视觉特征能够被 Qwen3-1.7B 语言模型理解，解决“图像向量不能直接进入语言模型”的问题。

图像CLIPProjectionQwen3Caption

关键做法

  • 数据：SA1B-Dense-Caption，训练集前 100000 条。
  • 冻结：CLIP 视觉编码器、Qwen3 LLM。
  • 训练：仅更新 MLP Projection。
  • 输入格式：随机指令“描述这张图片” + 图像 Caption。
  • 损失计算：只监督 assistant 回复部分，padding 使用 -100 忽略。

06 / Stage 1 Implementation

Stage 1 的代码逻辑

# Stage 1 核心策略
model = LlavaForCausalLM(CLIP_PATH, LLM_PATH)

# 冻结视觉编码器和语言模型
for p in model.vision_tower.parameters():
    p.requires_grad = False
for p in model.llm.parameters():
    p.requires_grad = False

# 仅训练 Projection
loss = model(pixel_values, input_ids, labels)
loss.backward()
optimizer.step()

# 根据 eval/ppl 保存最优 Projection 权重
if eval_ppl < best_eval_ppl:
    torch.save(model.projection.state_dict(),
               "stage1_projection_best.pt")

Projection 单独训练策略

CLIP 和 Qwen3 已具备较强的视觉表征与语言生成能力。Stage 1 的主要矛盾不是重新学习视觉或语言，而是建立视觉特征到语言嵌入空间的连接，因此只训练中间投影层更稳定，也更节省显存。

  • CLIP 输出保留 197 个 token，包含 CLS 和 14×14 patch 空间信息。
  • Projection 使用 Linear → GELU → Linear，将 768 维映射到 Qwen3 hidden size。
  • 视觉 token 前置拼接到文本 embedding 前，视觉位置 label 全部设为 -100。

07 / Stage 2 Instruction Tuning

Stage 2：多模态指令微调

训练目的

让模型从“能够描述图像”进一步变成“能够围绕图像回答用户问题”，支撑视觉问答、多轮对话和更真实的交互场景。

  • 加载 Stage 1 训练得到的 Projection 权重。
  • 冻结 CLIP，训练 Projection + Qwen3 LLM，强化图文条件下的回答能力。
  • 使用 CogVLM-SFT-311K 中的单轮与多轮对话数据，固定随机种子划分 2% 评估集。
  • 通过完整前缀编码再取差值，避免 BPE 分词边界导致 labels 错位。
  • 使用梯度裁剪 max_norm=1.0，降低全参数微调时的训练不稳定风险。

实验指标

Eval PPL≈ 7.5912

09 / Stage 3 LoRA Persona Adaptation

Stage 3：LoRA 人格适配

训练目的

在不重新训练完整模型的情况下，让同一个 Mini-LLaVA 具备不同回复风格，从而增强系统展示的趣味性和辨识度。

  • 加载 Stage 2 通用多模态权重。
  • 冻结 vision_tower 与 projection。
  • 对 Qwen3 的注意力和 MLP 层注入 LoRA。
  • 使用蒸馏后的风格 JSON 训练 adapter，通过不同 adapter 实现“默认助手 / 霸道总裁 / 中二少年”等模式切换。
回答风格客观、简洁、专业，适合常规图像描述和视觉问答。

10 / LoRA Implementation

LoRA 的参数高效微调逻辑

lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj"
    ],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

model.llm = get_peft_model(model.llm, lora_config)

# 保存 LoRA adapter，而不是保存完整模型
model.llm.save_pretrained("checkpoints/lora_adapter")

LoRA 阶段的能力边界

LoRA 主要改变语言表达风格，并不重新提升视觉识别能力。视觉理解能力主要来自 Stage 1 的模态对齐和 Stage 2 的指令微调。

  • 部署时使用 load_adapter 同时加载多个 LoRA 目录。
  • 默认助手调用 disable_adapters()，人格模式调用 set_adapter()。
  • adapter 体积远小于完整模型，便于保存、切换和复现实验。

11 / Innovation and Design Highlights

本系统的创新点与完成度

训练闭环完整

从 Stage 1 模态对齐、Stage 2 指令微调到 Stage 3 LoRA 适配，形成可解释、可复现的实验路线。

轻量化架构

使用 CLIP + 2 层 MLP + Qwen3-1.7B，在较小参数规模下实现可交互的视觉问答系统。

标签掩码精细

训练时只监督 assistant 回复，视觉 token、用户问题和 padding 全部屏蔽，任务目标更清晰。

多轮构造稳健

对话样本采用“完整前缀编码再取新增 token”的方式，避免模板和 BPE 边界造成错位。

人格切换低成本

LoRA adapter 独立保存，部署时可动态启用或关闭，不需要维护多份完整模型。

演示链路可访问

Gradio 服务提供图像上传、对话、二维码访问；本展示网站负责清晰呈现实验路线和系统闭环。

12 / Inference Pipeline

系统推理流程

1用户上传图像并输入问题
2空问题时自动补全“请描述这张图片”
3根据下拉框启用或关闭 LoRA adapter
4历史对话写入 chat template
5图像变换为 224×224 标准输入
6模型生成回答并清洗特殊标记
gen_kwargs = {
    "max_new_tokens": 256,
    "repetition_penalty": 1.15,
    "pad_token_id": tokenizer.pad_token_id or tokenizer.eos_token_id
}
关键点：推理阶段仍然复用训练时的图像预处理与 chat template。图片存在时拼接 visual_embeds 和 text_embeds；图片为空时退化为纯文本对话，保证系统不会因缺少图像直接中断。

15 / Training Results and Functions

Stage 1 从随机 Projection 开始，训练初期 loss 下降较快，后期逐渐趋缓。最终 Eval Loss 约为 1.5723，说明视觉特征到语言嵌入空间的基础对齐已经形成。

问答能力形成

Stage 2 任务包含开放式视觉问答和多轮对话，目标空间比 caption 更复杂。曲线下降后稳定在约 2.0270，表明模型已从描述能力扩展到图文指令跟随能力。
